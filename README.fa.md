# کاشی‌مهتاب — ثبت تولید و گزارش مدیریتی کارخانه‌های کاشی

پروژه Django با پایگاه داده PostgreSQL، رابط فارسی RTL، فونت محلی Vazirmatn، ورود دستی تولید، گزارش‌گیری و خروجی Excel/PDF.

**وضعیت تحویل:** کد قابل استقرار روی سرور مستقل است. این پروژه روی Sites منتشر نشده و نشانی آنلاین عملیاتی ندارد؛ میزبانی فعلی Sites مسیر پشتیبانی‌شده اجرای این پشته Django/PostgreSQL را ندارد. بک‌اند به فناوری دیگری تغییر نکرده است.

## شروع سریع با Docker

پیش‌نیاز: Linux، Docker Engine و افزونه Docker Compose. پوشه پروژه را روی سرور باز کنید.

```bash
cp .env.example .env
python3 -c 'import secrets; print(secrets.token_urlsafe(64))'
```

مقدار خروجی فرمان را در `DJANGO_SECRET_KEY` بگذارید. `POSTGRES_PASSWORD` را با یک رمز اختصاصی قوی جایگزین کنید. برای کاربران رمز پیش‌فرض وجود ندارد. دامنه یا IP واقعی را به `DJANGO_ALLOWED_HOSTS` اضافه کنید؛ `localhost,127.0.0.1` برای healthcheck باقی بمانند. در `DJANGO_CSRF_TRUSTED_ORIGINS` نشانی کامل HTTPS دامنه را درج کنید.

```bash
docker compose build
docker compose up -d db
docker compose run --rm web python manage.py migrate
docker compose run --rm web python manage.py createsuperuser
docker compose run --rm web python manage.py setup_basics
docker compose up -d web
docker compose ps
```

`createsuperuser` نام کاربری و رمز انتخابی شما را می‌پرسد. مدیر اولیه به همه کارخانه‌ها دسترسی دارد. `setup_basics` فقط دو کارخانه، سه سایز و سه درجه اولیه می‌سازد؛ هیچ تولید یا کاربر نمونه نمی‌سازد. اجرای مجدد نام‌های تغییرکرده کارخانه‌های اولیه را بازنویسی نمی‌کند.

برنامه در `127.0.0.1:8000` روی خود سرور گوش می‌دهد. پشت Nginx یا Nginx Proxy Manager و HTTPS قرار دهید. نمونه تنظیمات در `docs/nginx.conf.example` است. بعد از راه‌اندازی HTTPS، `DJANGO_COOKIE_SECURE=1` باقی بماند. اگر پروکسی معتبر، هدر `X-Forwarded-Proto` را بازنویسی می‌کند، `DJANGO_TRUST_PROXY=1` قرار دهید؛ این گزینه برای پروکسی نامطمئن فعال نشود. Compose پورت دیتابیس را به بیرون منتشر نمی‌کند.

اگر Nginx Proxy Manager در کانتینر دیگری اجرا می‌شود، کانتینر وب را به شبکه مشترک پروکسی اضافه کنید و مقصد پروکسی را نام سرویس وب و پورت ۸۰۰۰ بگذارید. `127.0.0.1` داخل کانتینر پروکسی، خود همان کانتینر است.

برای آزمایش اولیه HTTP با تونل SSH، موقتاً `DJANGO_COOKIE_SECURE=0` و `DJANGO_CSRF_TRUSTED_ORIGINS=http://localhost:8000` تنظیم کنید، سپس:

```bash
ssh -L 8000:127.0.0.1:8000 username@server-ip
```

در مرورگر سیستم خود `http://localhost:8000` را باز کنید. بعد از تغییر `.env` سرویس را بازسازی کنید:

```bash
docker compose up -d --force-recreate web
```

## ترتیب راه‌اندازی کسب‌وکار

۱. با مدیر اولیه وارد شوید. داشبورد خالی نشان داده می‌شود؛ این طبیعی است.
۲. در «اطلاعات پایه»، نام کارخانه‌ها را اصلاح و سایزها را تعریف کنید. سایز در کل سامانه مشترک است.
۳. درجات را تعریف کنید. درجه با ترتیب ۱، درجه یک برای شاخص کیفیت است؛ رنگ هر درجه در همه نمودارها ثابت است.
۴. در «کاربران و دسترسی‌ها» کاربر بسازید و نقش و کارخانه‌های مجازش را انتخاب کنید.
۵. در «ثبت تولید»، کارخانه و تاریخ شمسی را انتخاب و متراژ واقعی را وارد کنید.
۶. گزارش‌ها را با فیلترهای ترکیبی یا گروه‌بندی مناسب دریافت کنید.

اطلاعات پایه دارای تولید گذشته حذف نمی‌شود. با خاموش‌کردن «فعال»، از انتخاب‌های ثبت جدید خارج می‌شود و گزارش‌های قبلی باقی می‌ماند. ویرایش رکورد قدیمی با گزینه غیرفعال فعلی همچنان ممکن است.

## نقش‌ها

| نقش | مشاهده و خروجی | ثبت/ویرایش/حذف | کاربران و اطلاعات پایه |
|---|---|---|---|
| مدیر سامانه | همه کارخانه‌ها | همه رکوردها | مجاز |
| کاربر ثبت تولید | کارخانه‌های مجاز | تمام رکوردهای کارخانه‌های مجاز | غیرمجاز |
| مدیر گزارش‌گیر | کارخانه‌های مجاز | غیرمجاز | غیرمجاز |

انتخاب کارخانه‌ها برای مدیر سامانه محدودکننده نیست؛ این نقش بنا بر تعریف دسترسی کامل دارد. کاربر بدون کارخانه مجاز، گزارش خالی می‌بیند. کنترل دسترسی در سمت سرور، رکورد مستقیم و خروجی نیز اعمال می‌شود. پنل `/admin/` برای مدیریت فنی است؛ مدل‌های عملیاتی در آن فقط خواندنی هستند تا ثبت‌های اصلی از مسیر دارای تاریخچه انجام شوند.

## تاریخ‌ها و اعداد

تاریخ را به شکل `۱۴۰۵/۰۶/۱۸` یا `1405/06/18` وارد کنید. تقویم از endpoint جلالی سرور ماه، تعداد روزها و روز شروع هفته را می‌گیرد. ماه و سال قابل تغییرند و تایپ مستقیم هم پشتیبانی می‌شود. محدوده انتخابگر سال ۱۲۰۰ تا ۱۶۰۰ است. اعتبارسنجی نهایی در سرور انجام می‌شود.

تاریخ تولید `DateField` میلادی استاندارد است. تبدیل جلالی فقط در مرز ورودی، نمایش و تعیین گروه زمانی رخ می‌دهد. زمان ثبت و ویرایش مستقل، timezone-aware و به وقت تهران نمایش داده می‌شود. شروع هفته شنبه است. روز ابتدا و انتهای فیلتر در گزارش حساب می‌شوند. ماه و سال بر اساس تقویم شمسی محاسبه می‌شوند.

متراژ مثبت با حداکثر دو رقم اعشار و حداکثر ۱۲ رقم صحیح پذیرفته می‌شود. جداکننده اعشار `.` یا `٫` است؛ جداکننده هزارگان در ورودی وارد نکنید. اعداد فارسی، عربی و انگلیسی پذیرفته می‌شوند. متراژ از ابعاد کاشی یا تعداد ردیف‌ها تخمین زده نمی‌شود.

## ثبت تولید و جلوگیری از تکرار

ثبت تکی و چندردیفی دارای شناسه درخواست UUID هستند. ثبت چندردیفی حداکثر ۱۰۰ ردیف دارد. اعتبارسنجی همه ردیف‌ها و ذخیره همراه Audit در یک تراکنش انجام می‌شود. ردیف نامعتبر باعث ذخیره ناقص نمی‌شود. جمع قبل از ذخیره در مرورگر با عدد صحیح صدم مترمربع محاسبه می‌شود؛ مرجع نهایی سرور است.

دو درخواست هم‌زمان از یک کاربر در PostgreSQL با قفل ردیف کاربر و قید یکتایی `(user, key)` محافظت می‌شوند. ارسال دوباره همان شناسه و همان داده، تولید تازه ایجاد نمی‌کند. همان شناسه با داده متفاوت رد می‌شود. توکن و سوابق ارسال را بدون طراحی سیاست نگهداری حذف نکنید.

چند نوبت با کارخانه، تاریخ، سایز و درجه یکسان مجاز است. اگر متراژ و توضیحات هم یکسان باشند هشدار تکرار نمایش داده می‌شود و ثبت مجدد نیازمند تأیید داخل فرم است. هشدار ردیف مشابه قید یکتایی تولید نیست.

ویرایش با نسخه رکورد انجام می‌شود؛ ذخیره روی نسخه قدیمی رد می‌شود تا تغییر هم‌زمان کاربر دیگری بازنویسی نشود. حذف نرم است: رکورد از جمع‌ها کنار می‌رود ولی Audit قبل/بعد، کاربر و زمان باقی می‌ماند. ورود مستقیم SQL یا تغییر دستی دیتابیس خارج از تاریخچه برنامه است و نباید مسیر کار روزمره باشد.

## محاسبات و گزارش‌ها

مبنای همه درصدها مترمربع و از نوع Decimal است؛ گردکردن فقط زمان نمایش و خروجی انجام می‌شود.

- سهم از نتایج فیلترشده: متراژ گروه ÷ جمع تمام نتایج فیلترشده × ۱۰۰.
- سهم داخلی کارخانه: متراژ گروه ÷ کل همان کارخانه در نتایج فیلترشده × ۱۰۰.
- ترکیب درجات: فیلتر درجه از صورت مربوط به محاسبه همه درجات و مخرج حذف می‌شود؛ تاریخ، کارخانه، سایز، ثبت‌کننده، جست‌وجو و حدود متراژ همچنان اعمال می‌شوند. سهم درجه یک همیشه نسبت به همه درجات این جامعه محاسبه می‌شود.
- گزارش تجمیعی از جمع متراژها ساخته می‌شود؛ میانگین درصد کارخانه‌ها نیست.
- در ماتریس، ستون متراژ هر درجه متأثر از همه فیلترهاست. ستون «درصد ترکیب» سهم واقعی آن درجه از همه درجات همان کارخانه/سایز است و فیلتر درجه بر آن اثر ندارد. دو ستون پایانی، جمع فیلترشده و مخرج همه درجات را جدا نشان می‌دهند.
- مخرج صفر: «— / داده کافی نیست». درصد صفر با نبود داده متفاوت است. اختلاف جزئی مجموع درصدها با ۱۰۰٪ بر اثر گردکردن توضیح داده شده و به‌صورت مصنوعی اصلاح نمی‌شود.

گروه‌بندی‌ها: ریز تولیدات، روزانه، ماهانه و سالانه شمسی، کارخانه، سایز، درجه، نوع کاشی و ماتریس پویا. برای تجمیع دو کارخانه کافی است هر دو را انتخاب کنید یا انتخاب کارخانه را خالی بگذارید تا همه کارخانه‌های مجاز در نظر گرفته شوند.

فیلترها در URL باقی می‌مانند. نمودارها به ریزرکورد مرتبط لینک دارند. روزهای بدون تولید در بازه روزانه صفر نمایش داده می‌شوند؛ بازه‌های بیش از ۱۲۰ روز برای خوانایی به نمودار ماهانه تبدیل می‌شوند. جدول و نمودارها از داده ثبت‌شده ساخته می‌شوند. جمع‌ها و خروجی‌ها مستقل از صفحه‌بندی‌اند.

## Excel، PDF و چاپ

Excel شامل «گزارش تولید» و «خلاصه مدیریتی» با جدول‌های سایز/درجه/کارخانه و نمودار است. متراژ عددی و درصد عددی با قالب `0.00%` ذخیره می‌شود. تاریخ خروجی عمداً متن شمسی قابل خواندن است؛ تاریخ مبنای دیتابیس همچنان DateField است. این خروجی تصویری از نتایج هنگام دریافت است، اتصال زنده به دیتابیس نیست. متن کاربران به سلول فرمول تبدیل نمی‌شود.

PDF با WeasyPrint، فونت تعبیه‌شده Vazirmatn، حروف متصل فارسی و A4 افقی ساخته می‌شود. سربرگ جدول در صفحات تکرار می‌شود. ماتریس‌های دارای درجات زیاد به بخش‌های سه‌درجه‌ای تقسیم می‌شوند و ستون‌های کارخانه/سایز و جمع در هر بخش تکرار می‌شود. چاپ نیز همین اطلاعات را دارد. دریافت فونت یا کد از CDN برای کاربر نهایی لازم نیست.

## اجرای مستقیم بدون Docker

Python 3.12، PostgreSQL 16 و کتابخانه‌های Pango/Harfbuzz لازم‌اند. روی Debian/Ubuntu:

```bash
sudo apt install python3-venv postgresql libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
```

با مدیر PostgreSQL یک نقش و دیتابیس با نام و رمز متناظر `.env` بسازید. برای اجرای مستقیم `POSTGRES_HOST=127.0.0.1` قرار دهید. سپس:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py setup_basics
python manage.py collectstatic --noinput
gunicorn config.wsgi:application --bind 127.0.0.1:8000 --workers 3 --timeout 120
```

`runserver` فقط برای توسعه است. تنظیمات اصلی همیشه PostgreSQL را انتخاب می‌کند و هیچ fallback عملیاتی به SQLite یا LocalStorage ندارد.

## داده آزمایشی

در یک دیتابیس جداگانه و خالی، پس از ساخت مدیر:

```bash
docker compose run --rm -e ALLOW_DEMO_DATA=1 web python manage.py seed_demo --username YOUR_ADMIN
```

چهار رکورد سناریوی شما برای `۱۴۰۵/۰۶/۱۸` ایجاد می‌شود. گزینه `--extended` داده بیشتر برای بررسی نمودارها ایجاد می‌کند. این فرمان روی دیتابیس دارای هرگونه تولید اجرا نمی‌شود. دیتابیس نمونه را وارد عملیات نکنید. اجرای عادی برنامه و migrations هیچ داده نمونه‌ای نمی‌سازند.

## آزمون‌ها و وضعیت اعتبارسنجی

```bash
# آزمون روی PostgreSQL؛ دیتابیس جداگانه test_<POSTGRES_DB> می‌سازد.
bash scripts/test-postgres.sh

# آزمون سریع مستقل بدون سرویس PostgreSQL؛ فقط برای تست:
DJANGO_SETTINGS_MODULE=config.test_settings python manage.py test production
```

کاربر PostgreSQL آزمون باید مجوز ساخت دیتابیس تست داشته باشد. برای CI از دیتابیس و اعتبارنامه مستقل استفاده کنید. تست هم‌زمانی فقط در PostgreSQL اجرا می‌شود.

نتیجه محیط تحویل و محدودیت‌ها در `docs/VALIDATION.fa.md` ثبت شده است. Docker و PostgreSQL واقعی در این محیط اجرا نشده‌اند و قبل از بهره‌برداری باید روی سرور هدف آزموده شوند. آزمون مرورگر واقعی/موبایل نیز اجرا نشده است.

## پشتیبان‌گیری

```bash
bash scripts/backup.sh
```

خروجی در `backups/` با نام زمان‌دار و قالب فشرده `pg_dump -Fc` ذخیره می‌شود. فایل‌های قبلی حذف نمی‌شوند. نسخه بکاپ را به فضای دیگری خارج از سرور منتقل کنید. `.env` را جدا، محرمانه و با دسترسی محدود نگه دارید. کلید نشست‌ها و تنظیمات استقرار نیز برای بازیابی لازم‌اند. Volume نام‌دار PostgreSQL با بازسازی کانتینر حفظ می‌شود؛ `docker compose down -v` داده را حذف می‌کند و برای کار عادی نباید اجرا شود.

## بازیابی امن در دیتابیس تازه

ابتدا وب را متوقف کنید. نام جدیدی برای دیتابیس مقصد انتخاب کنید تا نسخه فعلی حفظ شود. مثال زیر یک دیتابیس **تازه** می‌سازد؛ اگر وجود داشته باشد فرمان شکست می‌خورد.

```bash
docker compose stop web
docker compose exec db sh -c 'createdb -U "$POSTGRES_USER" tileproduction_restored'
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d tileproduction_restored --no-owner --exit-on-error' < backups/CHOSEN_BACKUP.dump
```

پس از موفقیت، `POSTGRES_DB=tileproduction_restored` را در `.env` قرار دهید. مقدار POSTGRES_DB در تصویر PostgreSQL فقط هنگام اولین مقداردهی volume دیتابیس خودکار می‌سازد؛ دستور `createdb` بالا به همین دلیل لازم است.

```bash
docker compose run --rm web python manage.py migrate
docker compose up -d --force-recreate web
```

تعداد تولیدات، چند گزارش مرجع و ورود کاربران را بررسی کنید. دیتابیس قبلی را تا تأیید بازیابی نگه دارید. بازیابی را دوره‌ای روی سرور آزمایشی تمرین کنید.

## محدودیت‌های ظرفیت و استقرار

محاسبات گزارش در حال حاضر رکوردهای فیلترشده را برای گروه‌بندی جلالی در حافظه پردازش می‌کنند. خروجی‌ها هم‌زمان در همان درخواست ساخته می‌شوند. برای آرشیوهای بزرگ، بازه زمانی را محدود کنید؛ ظرفیت دقیق با تست بار روی سرور هدف تعیین شود. صف خروجی، پردازش پس‌زمینه، کش تجمیعی و تست بار در این نسخه وجود ندارد. این موارد جلوی استفاده روزانه معمول را نمی‌گیرند اما سقف ظرفیت را بدون اندازه‌گیری نمی‌توان تضمین کرد.

HTTPS، دامنه، DNS، تنظیمات reverse proxy و زمان‌بندی بکاپ باید روی سرور هدف تنظیم شوند. این پروژه احراز هویت و نشست استاندارد Django دارد؛ بازیابی رمز توسط مدیر سامانه انجام می‌شود. ارسال ایمیل و ورود دو مرحله‌ای در دامنه این نسخه نیستند.

## ساختار کد

- `production/models.py`: اطلاعات پایه، تولید، نقش و کارخانه‌های مجاز، تاریخچه و شناسه ارسال.
- `production/services.py`: تغییرات اتمیک و کنترل ارسال تکراری/نسخه رکورد.
- `production/reporting.py`: فیلترها، درصدها و گروه‌بندی‌ها.
- `production/dates.py` و `forms.py`: تبدیل جلالی و اعتبارسنجی ورودی.
- `production/views.py`: صفحات، مدیریت و خروجی‌ها.
- `production/exports.py`: Excel و PDF.
- `templates/`، `static/css/app.css`، `static/js/app.js`: رابط اصلی، تعامل fetch و تقویم.
- `production/tests.py`: آزمون‌ها و سناریوی هم‌زمانی PostgreSQL.
- `requirements.txt`: وابستگی‌های مستقیم؛ `requirements.lock`: نسخه دقیق همه وابستگی‌های نصب‌شده.

فونت Vazirmatn با مجوز OFL در `static/vendor/Vazirmatn-OFL.txt` همراه پروژه است.

منابع فنی: [Django](https://www.djangoproject.com/download/) و [WeasyPrint](https://doc.courtbouillon.org/weasyprint/stable/). نسخه Django این پروژه 5.2.17 است.
